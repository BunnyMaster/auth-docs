# 数据权限方案设计

## 1. 概述与设计目标

### 1.1 背景与痛点

业务查询若靠开发手写 `WHERE create_user =?` / `dept_id IN (...)`，常见两个坑：

- **漏配泄密**：新方法忘加条件，直接越权。
- **逻辑漂移**：各模块对同一范围实现不一致，后期难对齐。

### 1.2 核心设计目标

1. **无感注入**：MyBatis-Plus 数据权限 Handler 在 SQL 层拼过滤条件，业务代码不感知。
2. **唯一裁决顺序**：注解强制、用户覆盖、角色合并、默认兜底，谁先谁后写死，不打架。
3. **功能权限与数据权限拆开**：普通 `ADMIN` 可以有接口通配 `*`，数据范围仍走 Scope，不自动全量。
4. **模型收窄**：不做 `CUSTOM`；部门维统一靠配置的部门 ID 列表（及闭包展开）控制。

## 2. 数据范围类型（Scope Type）

生效类型 4 种 + 注解占位 1 个。只有前 4 种会变成 SQL 条件；`DEFAULT` 不参与过滤计算。

> [!NOTE]
> 库表 `scope_type` 只存 `ALL` / `SELF` / `DEPT` / `DEPT_AND_CHILD`，不含 `DEFAULT`，也不提供 `CUSTOM`。列名以注解 `userColumn` / `dimensionColumn` 为准（默认 `create_user` / `dept_id`）。

| **枚举值** | **含义** | **对应 SQL 条件 / 行为** | **说明** |
| -------------------- | ---------- | --------------------------------------- | -------------------------------------------- |
| **`ALL`** | 全量数据 | 不附加过滤条件 | 超管硬旁路；也可来自 `user_scope` / `role_scope` 或注解强制 |
| **`DEPT`** | 指定部门（不含下级） | `alias.dimensionColumn IN (部门 ID 列表)` | 列表来自配置的 `scope_dept_ids`，不是“当前用户所属部门”自动推导 |
| **`DEPT_AND_CHILD`** | 指定部门及全部后代 | `alias.dimensionColumn IN (展开后的部门闭包列表)` | 锚点仍是配置的 `scope_dept_ids`；下级 ID 在登录/授权画像构建时展开 |
| **`SELF`** | 仅本人 | `alias.userColumn = {currentUserId}` | 无配置时的默认兜底 |
| **`DEFAULT`** | 注解占位 | 不直接参与过滤 | **仅作注解默认值**，表示“用画像里的 Scope” |

## 3. 裁决逻辑与生效优先级

**一句话总览**

- 运行时（Handler）：超管 `ALL` > 注解非 `DEFAULT` > 画像 `deptScope` > `SELF`
- 画像内（登录/授权构建）：`user_scope` > `role_scope` 宽松合并 > `SELF`

每次 SQL 拦截按“先命中先停”：

```
[1. 检查超级管理员名单] ──(是)──> [生效: ALL]
         │ (否)
         ▼
[2. 检查注解 @DataScope.scope()] ──(非 DEFAULT)──> [生效: 注解强制类型]
         │ (DEFAULT)
         ▼
[3. 读取用户上下文画像 (AuthProfile.deptScope)] ──(有生效范围)──> [生效: 画像 Scope]
         │ (无 / 空)
         ▼
[4. 兜底策略] ─────────────────────────────────> [生效: SELF]
```

> **分层**：步骤 1～2、读画像在 SQL 拦截（Handler）；`user_scope` / `role_scope` 合并在**画像构建**阶段完成。Handler 只吃算好的 `AuthProfile.deptScope`，不再现场查库。

### 3.1 详细判定规则

1. **超级管理员（`SUPER_ADMIN_USER_IDS`）**：强制 `ALL`。注解、`user_scope`、`role_scope` 都关不掉。画像构建时也对超管固化 `deptScope=ALL`（与 Handler 双保险）。
2. **注解硬覆盖（仅类型）**：`scope!= DEFAULT` 时，用注解类型覆盖画像类型；**不改部门 ID**。强制 `DEPT` / `DEPT_AND_CHILD` 时，`values` 仍取画像已有列表；列表空则 Fail-Closed。
3. **画像合并**（构建 `AuthProfile.deptScope`）：
    - 有 `user_scope` → 直接用（含 `SELF` 覆盖角色 `ALL` 的情况）。
    - 无 `user_scope` → 多角色 `role_scope` **宽松合并**：任一 `ALL` 则 `ALL`；否则有部门维时，含 `DEPT_AND_CHILD` 则结果为 `DEPT_AND_CHILD`，否则 `DEPT`，部门 ID 取并集；否则 `SELF`。
    - **普通 `ADMIN` 角色不得因 `isAdmin` 短路成 `ALL`，必须走上述合并。**
4. **兜底**：无任何配置 → `SELF`。

## 4. 关键流程说明

### 4.1 注解强制类型时的部门 ID（values）

注解只能改**类型**，不能写死部门 ID。

- 强制 `ALL` / `SELF`：不依赖部门 ID。
- 强制 `DEPT` / `DEPT_AND_CHILD`：直接用画像里已算好的 `values`。SQL 期**不会**再查闭包表展开；画像 `values` 为空 → `1 = 0`。

### 4.2 超级管理员 vs 普通 ADMIN

| **维度** | **超级管理员** | **普通 ADMIN 角色** |
| -------- | --------------------------------- | ---------------------------------- |
| **判定** | `userId ∈ SUPER_ADMIN_USER_IDS` | 持有 `ADMIN_ROLES`（如 `ADMIN`） |
| **功能权限** | 全量接口/菜单 | 可分配通配 `*` |
| **数据权限** | 硬 `ALL`，注解收不窄 | 与普通用户同一套 Scope（`user_scope` / `role_scope` / 注解） |

> 已废弃 `ignoreSuperAdmin`。要收窄 ADMIN 的数据范围，配 `user_scope` / `role_scope`，或在该方法上注解强制类型。

## 5. 组件与注解设计

### 5.1 `@DataScope`

挂在 Mapper 方法上，声明该查询要走数据范围：

```Java
@Target({ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
public @interface DataScope {
    /** 用户所有者列，SELF 用 */
    String userColumn() default "create_user";

    /** 部门/维度列，DEPT / DEPT_AND_CHILD 用 */
    String dimensionColumn() default "dept_id";

    /** 表别名，必须与 Mapper SQL 中该表别名一致 */
    String alias() default "d";

    /** 非 DEFAULT 则强制该类型；DEFAULT 走画像 */
    DataScopeStorageType scope() default DataScopeStorageType.DEFAULT;

    /** 条件生成器 */
    Class<? extends DataScopeHandler> handler() default DefaultDataScopeHandler.class;
}
```

### 5.2 Fail-Closed

下列情况统一拼 `1 = 0`，宁可空结果也不泄密：

1. 生效类型为 `DEPT` / `DEPT_AND_CHILD`，但画像 `values` 为空。
2. `alias` / `userColumn` / `dimensionColumn` 非法（防注入校验失败）。
3. 条件字符串生成失败或 JSqlParser 解析失败。

**无登录画像（`AuthProfile` 为空）**：不注入数据范围条件，依赖上层鉴权拦未登录请求；数据权限模块不在此处二次 Fail-Closed。

## 6. 边界与注意约束

1. **闭包不补展开**：注解强制 `DEPT_AND_CHILD` 时，只用画像现成的 `values`。若画像本身是 `DEPT`（只有锚点、未含子孙），强制成 `DEPT_AND_CHILD` **也不会**再展开子部门——需要子部门就应在配置侧写成 `DEPT_AND_CHILD`。
2. **`alias` / 列名必须对齐 SQL**：默认 `alias = "d"`，主表别名不是 `d` 时条件会挂错表或拼坏 SQL。
3. **ADMIN 功能 ≠ 数据全量**：`*` 只代表接口能调；列表仍被 Scope 裁。
4. **超管不可被注解收窄**：不能靠 `@DataScope(scope = SELF)` 让超管只看本人。审计类需求改账号判定策略，别改拦截器旁路。
