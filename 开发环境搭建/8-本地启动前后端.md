# 本地环境前后端启动指南

本文档用于指导开发人员如何在本地搭建并运行 `auth-server`（后端）与 `auth-web`（前端）项目源码。

在执行本文档之前，请确保已按照顺序完成以下前置准备文档的操作：

1. **《3- 中间件 -Compose》**：完成基础设施容器的部署。
2. **《4- 业务库初始化》**：完成基础数据库表结构与种子数据的导入。
3. **《5-Nacos 配置导入》**：完成 Nacos 配置中心的导入与本地参数修改。
4. **《6-Minio 或阿里云 OSS》**：按需配置对象存储服务。
5. **《7-Ip2region》**：按需配置 IP 定位数据库。

> 环境软件版本要求（Java, Node.js, Maven, pnpm 等）请参阅 **《1- 环境依赖清单》**。

## 1. 前置检查清单

在启动项目前，请逐一确认以下事项：

- [ ] Docker Compose 基础中间件服务（MySQL、Redis、Nacos、MinIO 等）已全部正常运行。
- [ ] 业务数据库建表 SQL 及初始数据已成功导入。
- [ ] Nacos 控制台中 `dev` 命名空间的配置已导入，且其中的数据库连接、Redis 地址、MinIO 秘钥等参数已修改为**本机实际环境地址**。

## 2. 源码获取与依赖安装

### 2.1 源码克隆

在本地工作目录中执行以下命令克隆前后端代码仓库：

```Bash
# 克隆前端仓库
git clone https://github.com/BunnyMaster/auth-web.git

# 克隆后端仓库
git clone https://github.com/BunnyMaster/auth-server.git
```

### 2.2 依赖安装

- **后端依赖编译**（在 `auth-server` 根目录下执行）：

    ```Bash
    mvn compile
    # 或执行打包安装：mvn install
    ```

- **前端依赖安装**（在 `auth-web` 根目录下执行）：

    ```Bash
    pnpm i
    ```

## 3. 本地启动服务（IDE / 本机进程）

后端服务启动时需指定激活配置文件环境为 `spring.profiles.active=dev`，并确保 BootStrap 配置文件中的 Nacos 地址（`server-addr`）与命名空间（`dev`）指向本地 Nacos 服务。

项目核心服务及默认端口分配如下：

|**组件名称**|**描述**|**默认端口**|**备注 / 启动方式**|
|---|---|---|---|
|**`auth-gateway`**|API 网关服务|`8080`|IDE 直接启动 Application 入口类|
|**`service-auth`**|认证鉴权微服务|`20001`|IDE 直接启动 Application 入口类|
|**`service-system`**|系统业务微服务|`20002`|IDE 直接启动 Application 入口类|
|**`auth-web`**|前端服务|`5173`|在根目录执行 `pnpm dev`（端口配置见 `.env` 中的 `VITE_PORT`）|

**相关控制台地址**：

> [!TIP]
>
> 若需要使用 Docker 容器化方式完整启动应用层服务（非 IDE 本机调试），请参考各仓库中的 `docker/` 目录以及文档 **《附录/部署/演示机部署》**。中间件常用命令请参阅 **《附录/常用命令/Docker Compose 命令速查》**。

- **Nacos 控制台**：`http://<宿主机IP>:19848/nacos`（默认账号密码详见 Release 版本的 Compose 配置，通常为 `nacos` / `nacos`）。

## 4. 结果验证与验收

启动完成后，请通过以下步骤验证本地环境是否成功跑通：

1. **网关连通性**：访问 `http://localhost:8080`，确认网关正常响应。
2. **前端服务**：访问 `http://localhost:5173`（若修改过 `VITE_PORT` 请以实际端口为准），能够正常加载登录页面。
3. **服务注册状态**：登录 Nacos 控制台，确认 `auth-gateway`、`service-auth` 和 `service-system` 均已成功注册至 `dev` 命名空间。
4. **登录测试**：使用初始种子账号登录系统。
    - **默认账号**：`Administrator`
    - **默认密码**：`Admin@123456`

## 5. 常见问题与风险排查

- **Nacos 参数配置不正确**
    若导入 Nacos 配置后未修改默认地址/密码（如仍指向样例 IP 或错误的数据库密码），项目编译能够成功，但启动后会提示数据库连接失败、网关路由异常或文件上传错误。
- **前置中间件或数据库丢失**
    若在基础中间件未启动或业务数据库未导入的情况下启动后端服务，会导致服务启动报错、前端菜单加载为空或权限鉴权失败。请严格按照步骤 1~5 完成初始化。
- **本地配置文件未覆盖**
    请检查各微服务本地 `bootstrap.yml` 或 `application.yml` 文件中配置的 `spring.cloud.nacos.discovery.server-addr`，确保其指向本地运行的 Nacos 实例，避免因指向远程默认配置导致连接超时。
