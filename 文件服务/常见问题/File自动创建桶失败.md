## File 自动创建桶失败

### 现象

控制台里刚删掉阿里云（或其它 S3 兼容）桶，马上重启 `service-system`，启动报创建桶失败 / 桶已存在；
但控制台里明明已经看不到这个桶了。

桶如果还在：启动一般只打「bucket already exists」类 info，**不会**因「已存在」把服务拉挂。

配置与公开地址说明见 [存储地址与配置](存储地址与配置.md)。

### 原因

启动逻辑是：先 `head` 桶 → 判定不存在再 `create`。

云厂商删桶后短时间元数据不同步很常见：`head` 以为没了，`create` 又说还在（或其它瞬时冲突）。
不是「已存在就该失败」写反了——桶真在时会跳过创建继续跑。

### 怎么办

1. 等一段时间再启（以官网为准）或临时换一个桶名验证是不是延迟。
2. 控制台确认同名桶已彻底删掉，没有「删除中」。
3. 仍失败：核对 `endpoint` / region / ak 是否指错账号或区域（和删桶延迟无关的另一类问题）。
