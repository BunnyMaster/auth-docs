# 存储地址与配置

## 痛点

每个云的「公开访问地址」长得都不一样。API 用来上传的域名，和浏览器最终打开的域名，经常不是同一个。混在一个字段里，要么上传挂，要么链接打不开。

## 怎么配

两套职责拆开：

| 字段 | 干什么 | 谁用 |
|------|--------|------|
| `endpoint` + ak/sk + `bucket` | 上传、下载、预签名 | SDK |
| `public-url`（可选）| 拼给前端看的公开直链 | 只做字符串拼接 |

有 `public-url`：公开地址 = `public-url` + 对象路径，**覆盖**从 endpoint 推断的结果。
没 `public-url`：按平台风格从 endpoint 推——MinIO 常用 path-style（`endpoint/bucket/key`），阿里云用 virtual-hosted（`bucket.endpoint/key`）。

启动时还会用同一套 `endpoint` 自动建桶；删桶后立刻重建踩坑见 [File 自动创建桶失败](File自动创建桶失败.md)。

### 示例（Nacos / `auth.file`）

MinIO（本机或内网，公开地址和 API 一样时可不配 `public-url`）：

```yaml
auth:
  file:
    default-platform: MINIO
    minio:
      endpoint: http://192.168.3.4:9000
      access-key: xxx
      secret-key: xxx
      bucket: auth-files-dev
      # public-url: https://files.example.com   # CDN / 反代时再开
```

阿里云（API 用区域 endpoint；浏览器用桶域名或 CNAME）：

```yaml
auth:
  file:
    default-platform: ALIYUN_OSS
    aliyun-oss:
      endpoint: oss-cn-shanghai.aliyuncs.com
      access-key-id: xxx
      access-key-secret: xxx
      bucket: bunny-auth
      public-url: https://bunny-auth.oss-cn-shanghai.aliyuncs.com
```

新平台也可以走统一表 `auth.file.platforms.<平台>`，字段同样是 `endpoint` / `public-url` / `path-style-access` 等；推断对不上就显式写 `public-url`。

> [!WARNING] 风险
>
> - **别把 CDN / `public-url` 填进 `endpoint`**。SDK 会拿它当 API 打，上传和签名一起挂。
> - `public-url` 不管上传成不成功；链错了只是浏览器打不开，API 侧仍可能正常。
> - 预签名 URL 的主机来自 `endpoint`，公开直链来自 `public-url`。内网 endpoint + 外网 CDN 时，两种链接域名可以不一样——这是预期，不是串配置。
